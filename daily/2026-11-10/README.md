### N01 Anima OmniCharacter：单角色白背景参考与风格分支分开

**适用方向：角色参考·画风搭配｜以单角色白底图保留身份，再按条件叠加画风。**

**设计思路：参考身份与画风分工｜先清理参考背景，再把画风条件放到独立加载步骤。**

- 原作者与原文：[Einnashe07／Einnashe](https://huggingface.co/Einnashe07/Anima-OmniCharacter)。本库概述，非全文转载或完整翻译。
- 原发布仓库创建于北京时间11月10日00:16，当前revision更新至01:29；首次收录。[固定模型卡](https://huggingface.co/Einnashe07/Anima-OmniCharacter/blob/b51de51512431409daa11c291fd0f22430d89e72/README.md)；[原节点项目](https://github.com/Einnashe/ComfyUI-Anima-OmniCharacter)。
- 作者说明：输入一张单角色参考，可以是特写、半身或全身；先去掉原背景，换成白背景。专用节点把参考控制LoRA用于参考分支，另需Anima模型、Qwen编码器和Qwen Image VAE。不能由单角色支持推断多人绑定能力。
- 画师标签仅部分支持，效果取决于标签和参考图。作者建议自有兼容画风LoRA另用Model Only加载器放在Apply节点前；示例本身只加载OmniCharacter，不能替作者补入某张图的私人风格LoRA。
- [固定示例JSON](https://huggingface.co/Einnashe07/Anima-OmniCharacter/blob/b51de51512431409daa11c291fd0f22430d89e72/anima_omnicharacter_workflow.json)可见1024×1536、30步、CFG4、euler_ancestral／normal、denoise1及seed生成后randomize。它们是这个JSON的值，不能补作全部showcase实值；本轮只读节点与连接，未验证运行有效性。
- 权重为Anima衍生，按作者链接的CircleStone条款使用；仓库提供SHA256SUMS，但没有下载权重计算比对。与库中SnapRef属不同作者／资源，不因都做角色参考就合并为同一模型。

### N04 原创角色LoRA：先定角色标准，再筛图与挑检查点

**适用方向：角色LoRA·数据筛选｜把身份标准、图集筛选和检查点判断分别处理。**

**设计思路：身份标准·双阶段筛选｜先写角色固定特征，再用指标缩小范围并人工看同条件图。**

- 原作者与原文：[loraproof](https://civitai.com/articles/38208)。本库概述，非全文转载或完整翻译。
- 《Building an Original Character LoRA That Stays On-Model: Miyu & Nyx》，北京时间11月10日01:36公开发布，创建时间是11月6日，区分草稿创建与首发；首次收录。
- 作者先写canon sheet：发型、眼睛、肤色、体型及缩略图可辨的固定特征；从大量候选中找重复稳定的一组，不用最好看的一张作为全部标准。再用初步v0以较低权重生成候选，按身份和形体两遍筛选，剔除近重复与风格漂移。
- 作者只做一轮回灌，担心重复循环放大错误；这是其两个角色的经验，不宣称其他任务一律只能一轮。文章没有公开完整测量算法、完整数据和对照日志，不能把测量描述当成可复用的已验证系统。
- 两项示例用Animagine XL4.0路线、kohya、rank16／alpha8；Miyu挑1250／1500步，Nyx挑750步，作者成品使用权重0.85。具体配方属于这两个角色，不是所有LoRA默认值；[Miyu](https://civitai.com/models/3030622)与[Nyx](https://civitai.com/models/3035217)本轮只保存链接，未深读资源页。
- 作者的核心取舍：指标先缩小候选，随后用相同提示和种子的整组图按角色标准人工判断，既不只追最高分，也不只挑单张。文章含委托服务信息，本库仅整理公开方法。
- 实际读取范围：文章正文全文、日期与模型链接；未看示例图、读取数据集或训练日志。
