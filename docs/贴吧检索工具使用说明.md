# 贴吧检索工具：游客态实测与使用

## 每日默认工具与备用约定

**每日首选 aiotieba 4.8.2，通过仓库的 [只读脚本](../scripts/tieba_readonly.py) 执行。Astron-tieba-mcp 仅留档备用，正常每日任务不启动、不重复检索，也不反复检查其依赖。** 选择依据是本次 aiotieba 已覆盖两吧的列表、搜索、正文、作者与日期，可直接输出结构化资料，且无需 MCP 服务层；这是按任务覆盖与运行开销作出的选择，未做两工具的耗时基准比较。

每日按以下顺序使用主工具：
1. 复用已有可用 Python 环境；新环境需要时仅准备 `scripts/requirements-tieba.txt` 中的 aiotieba 依赖，依照下文命令运行，不依赖本次临时目录长期存在。
2. 分别读取 stablediffusion 与 comfyui 的 CREATE 最新列表；结合上次成功检索时间分页，遇窗口边界或已收录内容后按需要停止。置顶、缺失日期或排序异常需单独核对，不能因一个旧帖就声称全部覆盖。
3. 使用全站最新搜索补充类别词与当日发现的新名称，再筛选实际吧名；按 tid／原帖链接去重，只对有阅读价值的候选读取正文。关键词无命中不等于工具失败。
4. 核对楼主首楼的真实日期、作者和读取楼层，完成一批即摘要归档；图片、楼中楼及附件未取得的部分另记，不重复拉取已保存且无变化的正文。

仅在 aiotieba 实际调用失败或无法取得必要字段、确有补读需要时，才考虑备用 Astron；启用时记录原因、版本、操作和取得范围，使用独立进程。备用也失败则如实记录限制并继续归档其他已完成来源，不循环切换、安装或重试。原来的 MCP 配置与实测记录保留作参考，正常任务不要求两工具都成功。

## 以当前环境直接运行

从仓库根目录使用已装好依赖的 Python：

```bash
/workspace/research/tieba_tool_probe_20261030/venv/bin/python scripts/tieba_readonly.py list --forum stablediffusion --limit 20
/workspace/research/tieba_tool_probe_20261030/venv/bin/python scripts/tieba_readonly.py list --forum comfyui --limit 20
/workspace/research/tieba_tool_probe_20261030/venv/bin/python scripts/tieba_readonly.py search --query "Anima 画师串" --forum stablediffusion --limit 20
/workspace/research/tieba_tool_probe_20261030/venv/bin/python scripts/tieba_readonly.py read --tid 11146103648 --limit 20
```

临时环境路径只适用于本次工作区。其他已授权的执行环境可用独立虚拟环境安装 `scripts/requirements-tieba.txt`，或用 uv 按需提供依赖：

```bash
uv run --no-project --with aiotieba==4.8.2 python scripts/tieba_readonly.py list --forum comfyui --limit 20
```

脚本输出结构化 JSON，包括原帖链接、吧名、作者、原始日期、文字及读取范围；不提供发帖、点赞、关注、私信等操作。

## 排序、时间与历史补查

- `list` 使用 CREATE 按发帖时间获取列表，用 `--page` 逐页读取。
- `search` 使用支持最新排序的全站搜索，`--forum` 在当前页结果中筛选准确吧名。当前页没有匹配不表示该吧没有相关分享。
- `--since YYYY-MM-DD --until YYYY-MM-DD` 仅筛选当前列表／搜索页，时间按北京时间，until 包含该日。不会自动翻完四个月。
- `read` 读取指定原帖的一页楼层文字，不做图像观察或读取全部楼中楼；核原帖日期应看 thread／楼主首楼，不把最近回复时间当原帖发布时间。
- 本次吧内关键词接口返回了2023–2024旧帖，因此不能把“搜索成功”等同于“都是近期内容”。

例：

```bash
uv run --no-project --with aiotieba==4.8.2 python scripts/tieba_readonly.py list --forum stablediffusion --page 1 --limit 20 --since 2026-06-30 --until 2026-10-30
```

## 备用归档：Astron MCP 依赖记录（每日不运行）

本次安装时，包的宽松依赖范围拉取了 mcp 2.3.0，出现 `mcp.server.fastmcp` 导入错误。固定到 mcp 1.30.0 后服务可运行：

```bash
uvx --from astron-tieba-mcp==0.1.7 --with mcp==1.30.0 astron-tieba-mcp
```

aiotieba 与 Astron 包在同一 Python 进程共同导入时出现 protobuf 名称重复。本次分别使用独立进程成功；同一虚拟环境内可以分别运行，脚本只导入 aiotieba。
