# 社区分享收录规范与每日汇总模板

本库以每日广泛搜索、发现和汇总生图社区分享为主，尊重原作者成果，保留原文入口，方便查阅与交流。执行方法见[每日搜索流程](每日生图搜索流程规划.md)，维护见[维护指南](资料库维护指南.md)，搜索技能见[SKILL.md](../skills/image-workflow-research/SKILL.md)。

## 两类检索

- **每日广泛发现（主流程）**：无需具体差距、参考图或本地不足，逐平台查找模型、工作流、提示词、教程和实践经验。按分享价值、可学习性、来源质量和新增信息筛选。
- **认识差距后的主动搜索（辅助专题）**：有明确问题或改进要求时，定向寻找近目标示范，按需补齐配方、比较方案和提出建议。

每日定时任务默认第一类，主动专题不替代广泛覆盖。相同日期可分节记录两类内容，避免将所有分享改写为解决本地问题的专题。

## 来源与内容范围

固定检查：
1. 百度贴吧 **stable diffusion／stablediffusion 吧、comfyui 吧**，两个吧分别记录。
2. **bilibili**：具体视频、专栏及有帮助的讨论。
3. **Reddit**：具体分享帖、讨论及关键评论。
4. **Hugging Face**：模型卡、版本、示例及相关讨论。
5. **GitHub**：项目文档、Release、工作流、节点实现与问题讨论。
6. **Civitai 社区／论坛**：文章、教程、模型／版本讨论、工作流、带配方作品与社区经验。
7. 根据线索补充其他有效论坛、ComfyUI 社区、YouTube 与作者公开资料。

贴吧入口按用户提供的名称定位，保留 stable diffusion／stablediffusion 等别名，实际核对规范吧名与重定向。无法读取某个平台时记录访问限制，不以泛搜或其他平台冒称已覆盖。

内容涵盖后训练／特化模型、LoRA／LoKr、画师与条件混合、自动提示和选型、多主体、构图、姿态／深度约束、采样、VAE、精修及不同用途的提示词经验。Anima、Illustrious／IL、NoobAI 等为已有关注路线，也主动发现其他家族、作者、画风与用途。

## 搜索与筛选

- 广泛发现结合中英文类别词、近期内容入口、日期及新发现的模型／作者名；必要时加入日文。不能只搜索熟悉资源、热榜或既有问题。
- 优先自上次成功检索以来新增和实质更新，首次主要看近 7 天；必要时回看近 30 天或经典教程，注明真实日期与历史补录。
- 打开原帖，记录作者、版本、日期、读取范围和原文链接。摘要、视频简介、字幕、关键帧、评论和配置文件分别记录，不能冒称已读完整内容。
- 例图用于理解分享特点；主动专题才进一步评价目标匹配和任务难度。无图的有效教程仍可收录，有价值但配置不全的分享说明缺口。
- 通常精选 5–10 项仅为篇幅参考，不设最低条数。热度、节点数、词数、步数或分辨率不单独证明质量。
- 按原始链接、精确版本和实质变化去重；同源转载合并，更新写清变化并回链旧记录。无优质新增也记录真实覆盖与缺口。

## 适用方向短标注

每条教程及相关分享提供一行**适用方向**，放在详情标题下，并同步至当日速查表和总索引，让读者浏览时先判断是否与需求有关。

- 通常用 **1–3 个短标签＋一句话概括**，说明适合的任务／用途或主要技术方向；说明尽量简短，约 15–30 字即可。
- 可按内容选用人物插画、画风与上色、构图与姿态、多主体与关系、场景背景、提示词组织、LoRA 搭配、采样与精修、自动化工作流、兼容与排错等方向，允许新增更贴切标签。
- 如原文明示模型／版本或输入限制，补充必要限定，避免将专用教程标为通用。方向不清时写“适用方向待确认”，不得推断未提供的适用性或效果。
- 方向标注属于本库整理；原作者明确说明的用途可注明归属。标注帮助分类，不代表本库已验证收益。

格式示例（仅说明写法，不代表实际收录）：

> **适用方向：多主体·姿态控制**｜适合双人构图与动作关系约束。
>
> **适用方向：画风组合·LoRA 搭配**｜介绍特定基座的多风格配方组织。

## 美术风格与设计思路总结

风格相关内容按文章实际主题概括：具体画风写“美术风格方向：标签｜视觉特点”；通用的画风组合、表情、构图、上色、细节处理等经验写“设计思路：标签｜方法要点”。表格列统一为“美术风格／设计思路”，同步详情、当天速查表和总索引。技术安装、节点说明、训练配置等无需美术概括时表格留“—”，详情省略该行。

设计思路可以涵盖多种画风；标签概括作者讨论的做法，例如“表情设计”“风格组合”“镜头构图”“细节表现”。据已读文字即可整理这些方法。摘要优先告诉读者原作者分享了什么。作者描述与本库看图归纳注明归属，实际读取范围集中写在读取状态／详情；仅有文字也可总结设计方法。具体风格资料只概括已知特征或说明资源类型，未观察的身体、五官等无需逐项占位。

- 浏览层：通常 1–3 个风格标签＋一句简短视觉概括；不只写模型名、LoRA 名或画师名。
- 按内容概括整体风格／媒介（如日漫、厚涂、水彩、彩铅、水墨、版画、拼贴、半写实、摄影或三维质感），不限定为固定风格名单。
- 人物造型属于美术风格的重要组成。涉及人物时，按实际可见内容归纳以下方向；线条、上色和媒介特征继续保留。优先写最有辨识度的特点，不机械填满所有维度。

| 风格维度 | 可归纳的视觉特点 |
|---|---|
| 体型与比例 | 头身比、肩胯关系、躯干与四肢比例、轮廓体量、修长／圆润／健壮等造型倾向 |
| 脸型与五官 | 脸部轮廓、下颌、眼型与眼距、眉形、鼻口的简化或刻画程度、五官比例与组合 |
| 表情语言 | 眉眼与嘴部的处理、视线、含蓄或夸张程度、情绪传达及表情变化方式 |
| 姿态与形体塑造 | 动势、重心、肢体曲线、夸张与变形、体积和解剖处理 |
| 线条、色彩与完成方式 | 线条轻重、上色明暗、色彩氛围、笔触材质、写实／夸张程度与细节密度 |

- 将“多张示范支持的画风倾向”“角色自身设定”“单张图的内容／表情”分别说明。仅见单例时写“本例呈现……”，不把一个角色的体型、五官或某次表情推广为整个画风的稳定特征。
- 视觉概括聚焦实际可见、最有辨识度的特征。头像只概括可见部位；某画师、模型或 LoRA 名称本身不作为人物特征的依据。与结论直接有关的观察缺口在读取状态说明。
- 分别标明原作者的风格说明与本库实际看图归纳，链接对应例图／原文；文字描述用“按作者描述”。未看示范图写入读取状态。具体资源缺少风格文字时，可写“画风资源分享”或概括已知定位，避免通篇使用待确认占位。
- 纯技术资料表格留“—”，详情省略该项。风格与设计思路摘要属于本库整理，生成、复跑或视觉观察另记实际状态。

格式示例（仅说明写法，不代表实际收录）：

> **适用方向：人物插画·画风组合**｜介绍人物插画的风格配方组织。
>
> **美术风格方向：清爽日漫·细线赛璐璐**｜本例修长比例、圆润脸型，细线平涂、表情活泼。（本库看图归纳）
>
> **设计思路：细节表现**｜讨论 Anima 与 Illustrious 的图像细节增强方法。
>
> **设计思路：表情设计**｜按情绪和眼眉口组织人物表情提示词。

## 原作者署名与证据

每条分享保留**原作者、原帖标题、平台、日期与原文直达链接**，引导读者阅读完整原文并支持作者。贴吧给具体主题帖，B站给视频／专栏，Reddit 给讨论／关键评论，HF 给模型卡／版本，GitHub 给对应文档／Release，Civitai 给具体文章、模型／版本、作品或讨论。必要时定位楼层、时间点或章节。

原文引用／转载摘录、社区使用反馈、本库概述和学习备注分别标注，翻译或改编说明来源和改动；使用遵循原作者说明及适用许可。署名和链接不等同于额外转载授权。

涉及配置时区分“该图实际设置”“作者通用推荐”“本库拟补值”。未给出的内容写未说明／未取得，不为填表补造。具体示范尽量保存精确资源、字面正负提示、输入、有效设置、运行器／节点版本及元数据；完整配方不是广泛分享的收录门槛。

原作者说明、机制理解、运行行为、图像观察与用户认可分开。阅读、编译、加载、原配方复跑、偏离复现、局部采用与实际成图各按真实状态记录。日常汇总不自动触发安装、生图或实验。

## 日期目录与维护

- 日根目录：`daily/`，入口说明为[每日归档说明](../daily/README.md)。
- 当天目录：`daily/YYYY-MM-DD/`，日期和时间均用北京时间。
- 当天主汇总：`daily/YYYY-MM-DD/README.md`。同日重跑更新同一目录，不再创建 `daily/YYYY-MM-DD.md`。
- 需要时才建立当天的 `notes/` 或 `workflows/`，从主汇总回链；大模型、运行环境和缓存不入库。
- 先保存正文，再更新根目录[速查索引](../每日检索可速查总结.md)的日期、主题、状态与待办。
- 初始化目录标“待首次检索”，不计为已报道或已覆盖。首次实际归档后更新目录、索引和首页中对应初始状态说明。
- 更正保留日期与依据；写入失败如实说明。并发修改重读合并，不能覆盖新增内容。
