# 每日生图搜索流程规划

## 依据与目标

依据用户上传并已完整读取的 [image-workflow-research 技能](../skills/image-workflow-research/SKILL.md)、[检索与证据规则](../skills/image-workflow-research/references/search-and-evidence.md)、[示范学习与方法提炼](../skills/image-workflow-research/references/tutorial-learning.md)，结合本项目既有检索规范，制定每日资料检索、示范拆解和方法提炼流程。三份原文件随项目留存；后续执行读取当前版本。

检索分为认识差距后的主动搜索，以及无具体差距要求的每日广泛分享帖子搜索。前者围绕问题寻找近目标示范，后者持续发现并分享社区经验，积累可供今后参考的资料。两类均说明分享价值与来源，避免只罗列标题。以下是搜索与整理规划，不代表已实施生成器优化或取得视觉收益。

## 社区分享与整理说明

本流程服务于社区内容汇总与经验交流。感谢原作者公开分享教程、模型、节点和示范作品；收录时逐条标明原作者、原帖标题、日期与原文直达链接，引导读者回到原文。原文引用／转载摘录与本库概述、对照和学习建议分别标记；遵循原作者说明及适用许可。方法分析明确借鉴来源，并说明本库实际观察范围。

## 第一步：明确检索类型

读取本规范、[检索规范与日报模板](检索规范与日报模板.md)、[总索引](../每日检索可速查总结.md)与近期日报，确认本次类型并去重。

### A. 认识差距后的主动搜索

- 在已有明确问题、参考图或改进要求时，按线条语言、人物画法、光影上色、构图尺度与结构关系定位主要差距。
- 判断需要完整教程、配套提示、资源、参数依据还是故障反例。
- 明确输入方式与评价范围，按问题查找任务难度相近的示范。
- 例：“哪些公开方法有助于改善细线插画的阴影层次，并保持角色服装？”

### B. 每日固定的广泛分享帖子搜索

- 每日定时任务默认执行，不需要目标图、具体差距或本地待解决问题。
- 分平台广泛发现模型／后训练资源、LoRA／画师组合、工作流、提示词教程、示范配方与实践经验。
- 兼顾不同画风、用途、模型家族与作者，发现既有清单以外的新内容；不只看热榜或重复追踪熟悉资源。
- 以分享价值、可学习性、来源可靠度与信息新增量筛选，不要求与某个目标画风相似，也不要求每帖都能对照自制生成器。
- 例：“近期社区有哪些值得学习的模型、工作流和提示词分享？作者提供了哪些经验和适用条件？”

两类可并行，但须标注类型。主动专题不替代每日广泛覆盖，无具体差距时不为套模板而制造问题。模型、画师、LoRA 数量、词数及采样值不预设为质量标准。

## 第二步：按类型组合搜索

| 类型／阶段 | 搜索方式 | 进一步阅读 |
|---|---|---|
| 每日广泛发现 | 分平台近期浏览和类别查询；分享／教程／workflow／prompt／配方／新模型等词结合日期，动态追踪新作者、模型、用途和方法 | 原帖内容、示范、可用资源与经验，不要求已有问题 |
| 主动问题搜索 | 精确模型／后训练版本＋技术对象＋目标问题；需要时扩展其他路线 | 近目标图、任务难度、配置条件和方法依据 |
| 两类候选补查 | 作者／标题／视频编号／文件名／提示片段＋缺失项 | 原始配方、模型卡、元数据、版本及适用边界 |
| 有争议或需解释时 | 版本、前端、任务＋失败／冲突／failure／artifact 等 | 正反例与实际生效条件，不强制每帖展开实验分析 |

保留用户拼写与常见别名（stable diffusion／stablediffusion、光辉／Illustrious 等），结合站内搜索与 site: 查询。中文与英文交叉，必要时扩展日文。广泛发现不强制在每个查询中带特定模型或具体问题。

查询示例：
- 广泛发现：`ComfyUI 工作流 分享 教程`、`LoRA 配方 经验 分享`、`image generation workflow tutorial community`，结合平台及近期日期。
- 主动搜索：`Anima 线条 阴影 提示词`、`Illustrious 多主体 角色服装 工作流`。
- 候选补查：`具体作者或资源名 + workflow / metadata / negative prompt / 版本`。

先完成固定来源的广泛发现，再深入值得学习的候选；另有主动任务时记录对应专项。优先检查自上次成功检索以来新增与实质变化，首次近 7 天，必要时回看近 30 天或经典教程并标明补录。平台受限如实记载，并寻找可核实的原作者替代入口。

## 第三步：按平台寻找不同类型证据

| 来源 | 重点寻找 | 原始链接与定位要求 |
|---|---|---|
| stable diffusion 吧 | 后训练底模、画师／LoRA 配方、提示词、实际样图、失败案例与修正 | 具体主题帖；必要时记录楼层、附件和作者后续更正 |
| comfyui 吧 | 完整工作流、节点作用、结构控制、自动提示与多主体方案 | 具体主题帖与原工作流附件入口 |
| bilibili | 演示过程、提示词组织、节点连接、参数和前后对比 | BV 视频／专栏；记录关键时间点；简介、字幕、关键帧和实际观看分别标注 |
| Reddit | 实例配方、讨论中的适用条件、冲突、失败与作者答复 | 具体讨论及关键评论直达链接 |
| Hugging Face | 精确模型版本、训练／合并说明、示例配方、预测类型和兼容建议 | 具体模型卡、版本／revision 与示例文件 |
| GitHub | 节点真实作用、接口、版本变更、工作流示例、已知问题 | 对应文档／Release／工作流文件／Issue；必要时固定 commit |
| Civitai 社区／论坛 | 社区文章与教程、模型／版本讨论、工作流、带配方的作品分享与使用经验 | 具体文章、模型／版本、作品或讨论直达链接；记录作者、版本和实际读取范围 |
| 补充论坛与作者资料 | 弥补案例、语言、模型或技术路线缺口 | 具体论坛、板块与原教程帖，注明选择理由 |

两个贴吧逐一检索。吧名入口沿用检索规范，并实际核对规范名称和重定向。搜索结果、首页和转载只是发现入口，最终条目尽量回到原教程帖。

优先使用足够完成任务的连接工具、作者仓库、公开接口和原始文件；用户明确要求浏览器或已登录入口时沿用。受阻可换可用公开来源，但保留原平台未读缺口。论坛提供实测／失败线索，作者模型卡与节点实现核对精确版本、输入格式和参数含义。大量检索以机制、版本、平台、正反例和可执行候选的覆盖衡量；同源转载不算独立证据。冲突结论按版本、前端、任务及实际生效条件核查。

## 第四步：按类型筛选分享与示范

广泛发现先看分享价值、用途、方法信息和来源，结合例图记录视觉特点；不要求目标图相似或解决已知差距。无图的有效教程也可收录，说明实际取得的证据。主动搜索则优先目标匹配与任务难度，再决定深挖顺序。对有图的候选，检查实际可见内容：

- 线条：粗细变化、起收、轮廓和内部线、发束／衣褶组织。
- 人物：脸部、表情、手部、服装准确性、角色保持。
- 色面与光影：阴影层次、边缘、笔触、材质、手绘感。
- 构图与结构：景别、镜头、动作、主体数量、遮挡和关系难度。
- 输入与后处理：是否依赖参考像素、ControlNet、重绘、放大或人工修图。

作品画风、作者自述使用 AI、使用过某工具、某张图的实际配方是不同事实；不得凭画风相似推断底模、合并比例或画师串。指定创作者作为视觉目标时，仍须追查与具体图像对应的公开教程。

主动搜索中，视觉接近且任务难度相近的示范优先补齐资料；资料完整度用于判断可重放性，不能取代视觉匹配。广泛发现中，视觉特点只是理解分享的一部分，不用目标匹配淘汰其他有价值的社区经验。只有文字宣传或不可见缩略图的候选标为“视觉未核”，可作线索，不能声称效果匹配。

通常精选 5–10 项只是篇幅参考，不设最低数量，不为凑数降低依据要求。允许保留视觉很有价值但配方尚缺的候选，明确缺口和补查方向。

## 第五步：将配置对应到同一张示范图

广泛分享先保存原帖、作者、时间、分享要点、用途及已公开的资源与配置，未知项说明即可。对涉及具体图像或进入深入学习的示范，再保存下列同图配方记录；完整配方不作为所有广泛分享的收录门槛。避免将作者通用推荐拼成某图实际设置：

| 字段组 | 保存内容 |
|---|---|
| 来源与例图 | 原教程帖链接、标题、作者、日期、例图直达链接／截图来源、视频时间点或楼层、图的身份标识 |
| 精确资源 | 底模版本／revision／可得哈希，编码器、VAE，LoRA／LoKr 名称版本及各自权重，画师条件与混合方式 |
| 提示与输入 | 字面完整正负提示词、触发词、输入图与用途、结构控制、分辨率、主体与镜头要求 |
| 运行与配置 | 前端／运行器、ComfyUI 与关键节点版本、原始 JSON／PNG 元数据链接、采样器／调度器／步数／CFG／shift／denoise／种子／RNG、精度选项及后处理；未取得项保持未知 |
| 缺口与归属 | 每项值属于“该图实际设置”“作者通用推荐”还是“本地拟补值”；不明项写未取得，不推算补齐 |

保存原始文件状态、下载／安装状态、运行记录与效果评价，彼此不能代替；关闭／未连接项与隐式默认值也要记录。资源名称与别名不证明文件相同或不同；比较哈希先标明算法与覆盖范围，区分整文件 SHA256、tensor-payload／addnet、sshs_model_hash 与截断显示，不跨算法比前缀。需要核实兼容性时查权重家族、键名／shape、补丁映射及实际加载记录；可枚举或能加载不足以证明完全兼容。

保持字面正负提示与原配置可复制，不为了日报简短而改写原提示词。长配方可放在同一日报的折叠段或附录，摘要链接到对应条目；不强制为每个来源新建目录。示例图片及元数据无法取得时保留原入口并说明，不伪造完整配方。

记录实际读取范围：仅搜索摘要、已读正文、视频简介／字幕／关键帧／实际观看、配置文件读取、元数据读取、例图已观察。这些状态分别说明，不压成一个笼统的“已验证”。

## 第六步：按需拆解示范与对照

本步骤适用于主动专题及选定的深入学习案例。每日广泛分享可止于有来源的内容摘要、用途、公开配置与可学习经验，不要求每帖对照自制方案。

工作流配置与提示词组织分开比较。对有帮助的示范，至少回答“做了什么、依据是什么、可能服务什么职责、能迁移什么”。

**还原有效配置：**从最终输出反向追踪实际分支：加载器→模型补丁次序→条件编码→控制与混合开关→采样→解码→后期→保存。UI 列出资源、LoRA 强度有值或存在 LoadImage 均不证明生效。API 式配方保留真实请求、运行选项与返回参数，不冒称为 ComfyUI 节点图。推理配置核对预测类型、编码器／VAE、精度、采样／调度、shift、denoise 与 RNG；控制部分核对输入来源、作用层／时段、开关、补丁顺序及默认值。提示词权重、画师混合系数、LoRA MODEL／CLIP 强度、结构强度分别解释，跨架构不互换层数／权重格式；全局 LoRA 加条件分块不称区域隔离。

**拆解实际提示：**分别保存作者原词、UI 显示、编译器补词、分支文本及实际提交／最终编码文本；未捕获编码条件明确标注。核查身份作品、镜头、表情动作、可见服装、实体关系与场景光源的职责和顺序；trigger／画师／质量评分词的位置、次数、权重和版本；标签／自然语言写法，以及正负冲突、重复、镜头外条件与副作用。词数不等于 token 数，也不是质量分；不得从短标签示范推出长句无效，或从长描述推出关系已落实。

**核对解释：**追溯精确后训练版本的模型卡、caption／训练说明、节点文档／实现、同图元数据与反例。标明每项来源支持的是写法、参数含义、兼容性、机制还是效果经验；作者意图、实际运行行为和视觉收益分开。基模通用建议不覆盖后训练作者规则，相反证据与未证实项一并保留。自制方案已有有效部分继续保留，不为强调差异将整套方案归为错误。

| 比较对象 | 示范做法 | 自制方案现状／差异 | 教程或实现依据 | 可迁移优化 | 验证状态 |
|---|---|---|---|---|---|
| 工作流配置 | 节点、资源、连接、作用范围与有效参数 | 仅引用实际读到的对应版本；未取得写未取得 | 原帖、文档、实现位置 | 适用前提、改动组与保留条件 | 原作者说明／社区报告／机制假设／尚待复跑等 |
| 提示词组织 | 内容、角色、风格、镜头、区域归属与正负提示结构 | 保留字面提示比较，说明差异 | 同图配方及作者解释 | 可重用组织方法与失败边界 | 与配置验证状态分别记录 |

尚未取得当前自制方案时，只写“待对照”及所需文件／记录，不能凭历史聊天宣称当前生成器仍有某个缺陷。作者没有解释的职责标为机制假设，不把“画师 A 负责线条、B 负责阴影”或权重占比直接当作事实。

## 第七步：归纳分享经验，按需提出迁移方法

广泛发现汇总作者经验、适用场景和未来关注方向，无需先认定本地不足。只有主动专题或具体迁移需求才继续提出以下改动与验证建议。

将改动分为三组：

- **运行推理组**：模型／编码器／VAE 兼容性、采样配置、运行器与节点差异。
- **风格组**：画师条件、LoRA／LoKr、混合方式、风格提示及其权重。
- **内容镜头组**：角色与服装、动作、多主体归属、镜头构图、结构控制及其输入。

每条建议写清：遇到什么现象 → 优先改哪组条件 → 必须保留什么 → 预期观察什么 → 什么情况下撤回。先保留有效条件，按主要差距选改动；如果同时改变多个组，只评价整套方案，不单项归因。

本每日任务交付资料与方法，不自行启动生图、安装节点或批量实验。以后用户授权效果实验时：
1. 先以同版本原教程配方复跑，已有同版本真实复跑可复用。保留字面提示的顺序、重复、拼写和正负冲突，以及原资源、seed、尺寸、前端版本、RNG、有效采样／调度和控制；之后再分析，不先改写再称原样。作者通用推荐不覆盖该图元数据。
2. 缺件、替代与迁移偏离逐一记录，再安排接入自制方案的实验。
3. 原配方复跑与迁移实验分别保存实际提交／执行信息、有效选项、输出及反馈。看整图及原生脸、眼、发束、手、衣褶等相关局部，分别判断接近教程例图与接近用户目标的程度。
4. 阅读、编译、加载、实际成图、人工认可分别记录；用户认可只覆盖明确认可的范围。
5. 按真实状态写“已按原配方复跑／有偏离的复现／仅采用局部建议／仅读取／缺件待补”。改编失败不证明原教程无效，原教程有效也不证明接入必然改善。
6. 单例不推广为跨人物、景别、主体数或种子的稳定规律；成功原配方、人物迁移、单变量收益与跨目标稳定性逐层积累。人工认可保存原话、范围、对应实际图、执行配置和资源版本；助手评分、助手选中与局部表扬不提升为整体认可。直接复用须读取冻结执行记录，不重规划后称同一配方。

## 第八步：保存可速查结论，并承接下次检索

沿用已有归档结构：

- `daily/YYYY-MM-DD.md`：检索类型、来源覆盖、社区分享、公开配方及证据状态；主动专题另列问题、按需对照与迁移方法。
- `每日检索可速查总结.md`：日期目录、按问题／用途和资源检索的入口、待补缺与待验证清单。
- `docs/检索规范与日报模板.md`：通用选择、调整与判断规则；个图参数和用户反馈留在对应日报／案例记录，不把一次有效的数值变成通用硬规则。

保存前检查引用与结论是否对应、同图配方是否混入通用推荐、视觉判断是否真的看过图、是否误称已复跑或已实现。此为资料整理自查，不新增运行测试或派发子代理。

日报开头简短呈现：
1. 本期属于每日广泛发现、主动搜索，还是两类并行。
2. 最值得阅读的社区分享、适用场景与原教程链接。
3. 已公开的经验和主要信息缺口；有主动专题时另列具体差距、进展与建议。
