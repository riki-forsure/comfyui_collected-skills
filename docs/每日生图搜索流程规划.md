# 每日广泛搜索、发现与汇总流程

## 仓库主流程

本库主要工作是每日广泛发现生图社区分享、整理原作者经验并按日归档。**无需先提出具体差距，不把本地不足作为每日搜索前提。**

两类任务分别处理：
- **每日广泛发现**：固定执行，发现模型、工作流、提示词教程、示范配方、使用经验与讨论。
- **主动搜索专题**：在认识差距或有明确要求时开展，围绕问题深入找示范、查配置和学习方法。

两类可在同日汇总中分节，主动专题不能替代广泛覆盖。技能基于用户提供的[主文件](../skills/image-workflow-research/SKILL.md)与[检索参考](../skills/image-workflow-research/references/search-and-evidence.md)，按本库方向整理；[示范学习参考](../skills/image-workflow-research/references/tutorial-learning.md)用于按需深入。

## 1. 读取近期记录，确定时间窗

读取 AGENTS、README、收录规范、维护指南、skill、总索引和近期日期目录。识别已收录内容与待补信息，优先自上次成功检索以来的新增和实质更新；首次近 7 天，必要时回溯近 30 天或经典教程并标补录。

待办可帮助补查，但不限定广泛发现范围；无需选择一个本地问题才开始。

## 2. 逐平台广泛发现

| 固定来源 | 重点内容 | 保存的原文入口 |
|---|---|---|
| stable diffusion／stablediffusion 吧 | 模型、LoRA／画师配方、提示词与实践分享 | 具体主题帖，必要时楼层 |
| comfyui 吧 | 工作流、节点、结构控制、自动提示与经验 | 原帖和公开配置入口 |
| bilibili | 演示、教程、作者说明与对比 | 视频／专栏，必要时时间点 |
| Reddit | 分享帖、配方、反馈、失败与讨论 | 具体讨论与相关评论 |
| Hugging Face | 模型卡、版本、示例与作者讨论 | 模型卡／revision／示例 |
| GitHub | 工作流、节点、文档、发布与已知问题 | 具体文档、Release、文件或讨论 |
| Civitai 社区／论坛 | 文章教程、模型／版本讨论、工作流和带配方作品 | 具体文章、资源版本、作品或讨论 |

结合站内近期入口、类别词、日期与中英文查询，保留用户拼写和常用别名。发现不同作者、用途、画风和模型家族，避免只盯热榜或固定资源。根据线索补充其他有效论坛与作者资料，逐项记录实际覆盖和限制。

### 贴吧每日工具

默认仅用 aiotieba 4.8.2 的[只读脚本](../scripts/tieba_readonly.py)：分别浏览两吧 CREATE 最新列表，按时间窗分页；用全站最新搜索补充类别词和新线索，核对吧名与原帖日期，去重后再读值得收录的正文。复用可用依赖环境，按需准备主工具依赖；不因一次旧帖或关键词无命中断言完整覆盖／访问失败。已读资料及时归档。

Astron-tieba-mcp **仅留档备用**，正常每日不启动、不重复查询、不检查其依赖。仅主工具实际失败或缺必要字段而确有需要时考虑启用，记录切换原因与取得范围；不循环重试。版本、命令和边界见[工具说明](贴吧检索工具使用说明.md)。选择依据为实测任务覆盖与更少运行环节，未做耗时基准比较。

## 3. 阅读并筛选值得分享的内容

广泛发现看：
- 分享了什么，适合什么用途，读者可以学到什么。
- 是否有原作者原帖、版本条件、例图、配置或可核实说明。
- 相比已收录内容是否新增经验、路线、用途或实质变化。
- 已取得哪些信息，还有哪些未知。

例图用于理解视觉特点；无图的有效教程也可收录。完整配方、自制对照、目标画风相似都不是每日分享的统一门槛。热度、节点复杂、词数、步数或分辨率不单独证明质量。通常精选 5–10 项仅作篇幅参考，不设最低条数。

风格相关内容按文章实际主题概括：具体画风写“美术风格方向：标签｜视觉特点”；通用的画风组合、表情、构图、上色、细节处理等经验写“设计思路：标签｜方法要点”。表格列统一为“美术风格／设计思路”，同步详情、当天速查表和总索引。技术安装、节点说明、训练配置等无需美术概括时表格留“—”，详情省略该行。具体写法见[收录规范](检索规范与日报模板.md)。摘要优先告诉读者原作者分享了什么。作者描述与本库看图归纳注明归属，实际读取范围集中写在读取状态／详情；仅有文字也可总结设计方法。具体风格资料只概括已知特征或说明资源类型，未观察的身体、五官等无需逐项占位。

## 4. 补查原文与关键信息

追踪作者、原帖、版本页、分享文件、示范与公开元数据。原文引用／转载摘录、社区反馈、本库概述和学习备注分别标明，保留署名、标题、日期和直达链接，感谢原作者并引导读者阅读原文。

作者通用建议、同图实际设置与本库拟补值分开。实际读取正文、简介、字幕、画面、评论、配置和元数据的范围分别记录；未知保持未知。私人配方不推测补齐，作品画风相似不证明实际底模或画师串。

## 5. 建立当天目录，保存汇总

按北京时间建立或更新：
- `daily/YYYY-MM-DD/README.md`：当天主汇总，使用[日报模板](检索规范与日报模板.md)。
- `daily/YYYY-MM-DD/notes/`：按需的长笔记。
- `daily/YYYY-MM-DD/workflows/`：按需保存可依原作者说明使用的公开小型配置。

只有需要时建立可选子目录，不为每帖机械增加文件。同日重跑更新原目录。无新增、部分受限或未完成也记录真实状态；初始化占位不算执行完成或已经报道。

先保存当天正文，再更新[总索引](../每日检索可速查总结.md)的日期／主题入口、状态和后续关注。首次实际执行时更新对应目录、索引和首页的初始状态说明。

## 6. 按需开展主动搜索或深入学习

当有明确差距、参考图或改进要求时：
1. 拆分线条、人物、光影、构图与结构关系，明确输入方式和问题。
2. 用精确模型／后训练版本、技术对象与目标问题组合查询，寻找任务难度接近的示范。
3. 核对同一图像的精确资源、字面正负提示、实际有效配置、运行器／节点版本和可得元数据。
4. 工作流与提示组织分别学习；需要自制对照但当前版本未取得时标待对照。
5. 保存“示范做法→自制差异→原教程／实现依据→可参考方法→状态与范围”，保留自制方案已有有效部分。
6. 具体迁移建议按运行推理、风格、内容镜头三组写清改动、保留项、观察与撤回条件；多组同时变化只评价整套方案。

每日发现中某个案例值得深挖也可使用此方法，但不要求所有分享帖经过完整对照、机制解释和实验设计。详见[示范学习与方法提炼](../skills/image-workflow-research/references/tutorial-learning.md)。

## 7. 状态、去重与维护

按原始 URL、精确版本与实质变化去重。转载合并，旧配方保留版本范围；再收录写清变化并回链。更正记录时间和依据，失效链接记录真实状态并查找可核实的作者替代入口。

资料读取、原配方／偏离复现、实际成图和用户认可分别记录。本任务只搜索与汇总，不自动安装、生图或实验；日后有授权时再按原配方与偏离记录执行。提交冲突重读合并，写入失败明确未归档，不声称完成。

## 当次完成标准

- 每日广泛发现独立覆盖固定来源和两贴吧，未完成或受限之处可查。
- 条目有作者、原文、分享要点、用途和实际证据范围。
- 本库备注与原作者内容分开，未知信息不补造。
- 当天目录和总索引已保存，或如实交付未能保存的内容。
- 主动专题如有开展，单列问题和范围；无专题不强制创造差距。
