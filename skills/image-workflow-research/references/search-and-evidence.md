# 检索、读取与候选筛选

## 组合搜索词，覆盖用户指定平台

从“精确模型/后训练版本 + 技术对象 + 目标问题”组合查询。保留用户原有搜索词，同时加入别名、英文和版本词，例如：

| 搜索方向 | 可用组合 |
|---|---|
| 画师串与LoRA串 | `anima 画师串`、`anima lora串`、`anima artist mix workflow`、`Illustrious LoRA stack` |
| 模型差别 | `光辉 Illustrious 画师串`、`MOSS Base SFT style LoRA`，追加精确后训练版本 |
| 目标画法 | 模型名 + `线条 / 人物 / 手绘 / 光影` 或 `linework / shading / style` |
| 指定作者 | 作者名 + `workflow / prompt / model / tutorial / 教程`，继续追踪本人公开说明 |
| 已知资源 | 文件名、教程编号、仓库名、版本ID、插件名或提示片段 |

用户点名百度贴吧的stablediffusion吧/comfyui吧、B站、Reddit时，各平台分别查找；搜索引擎结果只作为发现入口，不能用其它平台替代尚未读取的指定平台。站内搜索与`site:`可结合，保留用户提供的拼写与常见别名。

论坛经验与作者资料承担不同职责：论坛查实测、失败情况和资源线索；模型卡、节点文档与实现核对精确版本、输入格式和参数含义。遇到有价值的例图，沿其作者、原帖、分享文件和PNG元数据继续追溯。

“大量检索”以关键机制、版本、来源渠道、正反例和可执行候选的覆盖为目标，不靠堆标题或同源转载数量。相同结论的转载不算独立证据；遇到冲突时比较版本、前端、任务和实际生效条件。

## 用合适入口读取，记录实际取得内容

优先使用足够完成任务的连接工具、作者仓库、公开接口与原始文件；用户明确要求浏览器或已登录平台时沿用该入口。某入口受阻时，可继续读取可用的公开作者资料，并保留原平台缺口。

每条关键来源标明实际读取层级：正文、完整工作流、原生例图、视频画面/字幕及范围、简介、评论及范围、搜索摘要或未取得。API成功不代表已读全部正文；视频简介、低清抽帧和完整原生示范分别记录。没有取得的参数和私人配方保持未知，不用推测补成“原教程”。

作品画风、作者自述使用AI、使用过某工具与该图的实际配方是不同事实。指定创作者用于视觉目标时，仍需寻找可对应图像的公开教程；不能凭相似画风认定底模、合并比例或画师串。

## 先看图，再看复现完整度

按以下问题选择候选，而非只按下载方便程度：

1. 线条、人物、色面和光影是否接近用户目标？是否涉及同类景别、主体数量、动作和光照难度？
2. 能否把该图与完整提示、精确资源、有效工作流及参数对应？是否有原生PNG元数据？
3. 输入职责、模型家族、运行器、依赖和资源获取是否适合当前任务？
4. 教程说明的收益是否有图像、对照或反例，作者是否说明适用边界？

近目标但缺件的示范保留优先补件位置；资料完整但画法偏离的教程不抢占目标实验。头像示范不直接证明全身、手部或双人互动能力。

## 建立可追溯的资源记录

按实际需要合并到任务记录，保留以下信息：

- URL、作者、平台、查询词、读取日期及正文/视频定位、内容层级和缺口。
- 例图原文件或来源；与其对应的提示、负向、seed、尺寸、输入方式和后处理。
- 底模/后训练精确版本、架构/预测类型、编码器、VAE、LoRA与trigger、前端和节点版本。
- 作者范围、该图实际值、本地补值，以及关闭/未连接项和隐式默认值。
- 原始文件状态、下载/安装状态、运行记录与效果评价，不能互相代替。

文件名与别名不证明资源相同或不同。比较哈希时核对算法与覆盖范围，区分整文件SHA256、tensor-payload/addnet哈希、元数据`sshs_model_hash`及截断显示；不同算法不直接比前缀。核对权重家族、键名/shape、补丁映射和实际加载情况，不能因“可枚举/能加载”宣称完全兼容。

模型资料随版本变化；再次应用时核对影响当前结论的版本条件，不把历史论坛经验提升为新版本默认。

## 从资料收集进入学习

选中示范后，按 [示范学习与方法提炼](tutorial-learning.md)处理。检索记录回答“找到什么、证据到哪”；学习记录回答“它怎么做、比自制方案有什么差异、可迁移什么、还有什么未证实”。具体模型推荐和数值留在带版本的案例资料中。
